Screenshots

Hold the guide button and the right bumper together — the same chord a Steam Deck takes a picture with — or press Print on a keyboard.

The screen flashes white, the shutter sounds, and the picture of the display you are driving lands in the Screenshots folder inside your pictures, where it is on the Images shelf a moment later. Print works whatever you hold with it, so a hand trained on any other desktop's variant gets it right; a keyboard with no Print key can use Ctrl+Shift+3.

Screen sharing

OBS records the session and Discord shares it, the same way they do on any other Linux desktop — through the screen-sharing portal.

When an application asks, the shell asks you which display to share, on its own panel. Nothing can record the screen without that answer: programs cannot grab it behind your back.

Choosing a file

A browser wanting a photo to upload, an editor wanting somewhere to save, a game wanting a folder for its mods — they all get the shell's own chooser.

Other desktops' file dialogs are a tree, a list and a text field, and none of them can be reached with a controller. Here the question is answered in the Files column you already know, on a large pane of glass; a save opens on Save here with the name already under it. Show in folder in a browser walks the bar into that folder in Files too, instead of starting some other file manager over the shell.

Password prompts

Mounting a disk, installing an update, changing a system setting — when the system needs an administrator to agree, the shell asks, on its own panel, with a sound so you notice.

The password is checked by the system itself, never by the shell, and is wiped from memory as soon as it has been handed over. Without an agent like this, a desktop simply refuses those requests with nothing on screen to allow them.

Keeping it awake

A film playing or a game running keeps the screen lit and the machine awake, the way you would expect — including games from a Flatpak, like everything Heroic or RPCS3 from Flathub starts.

When nothing is holding it, the screen dims, goes dark and sleeps on the waits you set under Power.

Works with your apps

Ordinary Linux applications run here as they are: native Wayland programs, X11 programs through Xwayland, and Flatpaks.

A launched application fills its screen — the console model — and the guide is how you move between them. Games running natively on Wayland through Proton get what they ask for: explicit sync, tearing for the lowest latency, and HDR passed through to the display.
