एक विंडो में आज़माएँ

इसे देखने के लिए आपको अपना डेस्कटॉप छोड़ने की ज़रूरत नहीं। Rust 1.89 या नया और बिल्ड डिपेंडेंसी इंस्टॉल हों, तो एक ही स्क्रिप्ट LineXinBar बनाकर उसे आपके मौजूदा सत्र में एक विंडो की तरह खोल देती है।

git clone https://github.com/Petexy/LineXinBar.git
cd LineXinBar
./scripts/run-nested.sh

नेस्टेड डेस्कटॉप को अपनी सत्र बस मिलती है, इसलिए उसके अंदर खोले गए ऐप्लिकेशन अंदर ही रहते हैं। विंडो बंद करने पर यह ख़त्म हो जाता है। ./scripts/run-nested.sh 3 एक की जगह तीन वर्चुअल डिस्प्ले खोलता है, ताकि कई डिस्प्ले वाला हिस्सा आज़माया जा सके।

हर डिस्ट्रीब्यूशन के लिए बिल्ड डिपेंडेंसी:

sudo pacman -S --needed rust pkgconf clang wayland libinput seatd systemd-libs libdrm \
    mesa libxkbcommon libglvnd libx11 libxcb libxcursor libxi libxkbcommon-x11 \
    alsa-lib ffmpeg libpipewire
sudo apt install build-essential pkg-config cargo clang libwayland-dev libinput-dev \
    libseat-dev libudev-dev libdrm-dev libgbm-dev libxkbcommon-dev \
    libegl1-mesa-dev libx11-dev libxcb1-dev libxcursor-dev libxi-dev \
    libxkbcommon-x11-dev libasound2-dev libavcodec-dev libavformat-dev \
    libavutil-dev libswscale-dev libpipewire-0.3-dev

Debian 13 पर Rust rustup से लें: डिस्ट्रीब्यूशन वाला Rust बिल्ड की ज़रूरत से पुराना है।

sudo dnf install cargo pkgconf-pkg-config clang wayland-devel libinput-devel \
    libseat-devel systemd-devel libdrm-devel mesa-libgbm-devel \
    libxkbcommon-devel mesa-libEGL-devel libX11-devel libxcb-devel \
    libXcursor-devel libXi-devel libxkbcommon-x11-devel alsa-lib-devel \
    ffmpeg-free-devel pipewire-devel

पैकेज इंस्टॉल करें

Arch, Debian और Ubuntu, और Fedora के लिए तैयार पैकेज हर GitHub रिलीज़ के साथ लगे होते हैं। या उन्हें रिपॉज़िटरी से खुद बनाएँ — तरीके उसी में हैं।

./packaging/build.sh arch -- --syncdeps

रिपॉज़िटरी के लिए एक PKGBUILD बनाता है और makepkg चलाता है; पैकेज packaging/out/arch/ में पहुँचते हैं।

sudo apt install dpkg-dev build-essential pkg-config clang rustup \
    libasound2-dev libgbm-dev libavcodec-dev libavformat-dev libavutil-dev \
    libswscale-dev libinput-dev libpipewire-0.3-dev libseat-dev libudev-dev \
    libxkbcommon-dev
./packaging/build.sh debian

बिल्डर पहले सब कुछ जाँचता है और अगर कुछ कम हो, तो उसे एक ही apt install पंक्ति में बता देता है।

sudo dnf install rpm-build dnf5-plugins git-core
sudo dnf builddep packaging/fedora/lxb-desktop.spec
./packaging/build.sh fedora

बाइनरी और सोर्स RPM packaging/out/fedora/ में कॉपी होते हैं। बनाने के लिए एक fedora-toolbox कंटेनर काफ़ी है।

nix build path:.#linexinbar          # the whole desktop, as one derivation
nix build path:.#lxb-compositor      # the compositor alone

रिपॉज़िटरी एक पिन किया हुआ flake है, और nix-build packaging/nix flakes के बिना भी चलता है।

lxb-compositor और lxb-desktop इंस्टॉल करें: कंपोज़िटर, और शेल अपने पोर्टल, अपडेट कोऑर्डिनेटर और सत्र एंट्री के साथ।

GitHub पर रिलीज़पैकेजिंग गाइड

सत्र शुरू करें

पैकेज इंस्टॉल हो जाने पर, अपनी लॉगिन स्क्रीन की सत्र सूची से किसी भी दूसरे डेस्कटॉप की तरह LineXinBar चुनें।

टेक्स्ट कंसोल से lxb --shell पूरा सिस्टम शुरू करता है; शेल से बाहर निकलने पर खाली स्क्रीन छोड़ने के बजाय लॉग आउट हो जाता है। Console Experience लॉगिन स्क्रीन इसके साथ चलने के लिए बनी है और शेल को एक लगातार तस्वीर की तरह सौंपती है।

सेटिंग ~/.config/lxb/ में रहती हैं — ज़्यादातर शेल का अपना सेटिंग कॉलम इन्हें लिखता है, और सभी को हाथ से पढ़ा और बदला जा सकता है।

कॉन्फ़िगरेशन संदर्भ

वैकल्पिक पैकेज

तीन इंटीग्रेशन अपने अलग पैकेज हैं, ताकि जो मशीन कभी कंसोल एम्युलेट नहीं करती वह इनमें से कुछ भी न ढोए। सत्र चलते हुए इनमें से कोई इंस्टॉल करें, और उसकी पंक्ति कुछ सेकंड में दिख जाती है।

lxb-retroarchRetroArch के ज़रिए आपके अपने कंसोल गेम, कोर और कवर आपके लिए खुद डाउनलोड होते हैं। lxb-heroicHeroic Games Launcher के Flatpak के ज़रिए आपकी Epic Games लाइब्रेरी। lxb-rpcs3RPCS3 के ज़रिए PlayStation 3 गेम, उनके वीडियो, संगीत और ट्रॉफ़ियों के साथ।

हर एक उसी शेल वर्ज़न से बँधा है जिसके साथ वह बना था। Steam को अपने पैकेज की ज़रूरत नहीं — बस Valve का Steam क्लाइंट चाहिए।

इसे क्या चाहिए

  • Linux, ऐसे ग्राफ़िक्स ड्राइवर के साथ जो डिस्प्ले चला सके (DRM/KMS) और एक चालू OpenGL ES ड्राइवर; अगर Vulkan ड्राइवर हो, तो उसका इस्तेमाल होता है।
  • systemd-logind या seatd, जो सत्र को उसके डिस्प्ले और इनपुट डिवाइस सौंपता है।
  • udev, ताकि स्क्रीन और कंट्रोलर लगाए जाने की ख़बर मिले।
  • वैकल्पिक: X11 प्रोग्राम के लिए Xwayland, ध्वनि और स्क्रीन शेयर करने के लिए PipeWire, इंटीग्रेशन के लिए Flatpak, बाहरी मॉनिटर की चमक के लिए ddcutil।

हार्डवेयर के बारे में सब कुछ चलते-चलते पता लगाया जाता है — हर डिस्प्ले, मोड और GPU — इसलिए आपकी मशीन के लिए पहले से कुछ भी कॉन्फ़िगर नहीं करना पड़ता।

हार्डवेयर

LineXinBar शुरुआती विकास में है। अब तक टेस्टिंग ज़्यादातर दो डिस्प्ले चलाने वाले एक AMD ग्राफ़िक्स कार्ड पर और नेस्टेड सत्रों में हुई है।

कुछ भी उस हार्डवेयर से बँधा नहीं है — कई GPU वाला रास्ता मौजूद है — लेकिन दूसरे ग्राफ़िक्स निर्माताओं, हैंडहेल्ड और कई GPU वाली मशीनों को आज़माने के लिए और लोगों की ज़रूरत है। अगर आप इसे किसी नई चीज़ पर चलाएँ, तो क्या चला और क्या नहीं, इसकी रिपोर्ट सबसे काम की चीज़ों में से एक है जो आप भेज सकते हैं।
